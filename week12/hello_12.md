    - 페이지 라우팅
    - 라우팅: 경로를 지정하는 과정 ,데이터 전달을 목적으로 최적의 경로를 찾아 데이터를 전송하는 과정
    - 페이지 라우팅: 요청에 따라 적절한 페이지를 반환하는 일련의 과정
    - 서버사이드 렌더링: 웹 브라우저에서 URL로 서비스 요청, 경로 블로그 확인, 블록그html을 생성해 반환, 웹 서버에서 반환된거 보여줌, 웹 브라우저에 표시할 페이지를 웹서버에서 만들어서 전달,검색 엔진 최적화,.처음 접속할때 속도가 빠르다는 장점. 많은 연산을 수행해야 한다는 단점,, 과부화에 걸릴 위험성 있음
    - 클라이언트 사이드 렌더링: html 파일이 하나이기 때문에 사이드가 아닌 클라이언트로 페이지 라우팅, 웹 브라우저가 블로그로 서비스 요청, 인덱스와 html과 자바스크립트 애플리케이션인 리액트 앱을 반환. 사용자가 보는 페이지를 웹 서버가 아닌 브라우저가 완성,브라우전느 청므 접속할 때만 서버에게 데이터를 요청하며 페이지를 이동할 때는 별도의 요청하지 않음,서버가 자바스크립트 애플리케이션을 함께 제공하기 때문에 처음 사이트에 접속할때는 서버 사이드 렌더링보다는 속도가 느림,페이지를 이동할 때는 브라우저에서 페이지를 직접 교체하기 때문에 속도가 훨씬 빠름
    - 리액트 라우터: Remix에서 제작한 오픈소스 라이브러리, 몇 줄만의 코드만으로 여러 페이지로 구성된 리액트 앱을 간단히 구축 가능
    - 설치,적용
    - 페이지 컴포넌트 만들기: 여러 페이지로 구성된 리액트 앱을 리액트 라우터로 만듦(홈,뉴,다이어리,에디트)
    - 홈: 인덱스 페이지 역할
    - 뉴:ㅣ: 새로운 일기 작성
    - 다이어리: 작성할 일기를 상세히 볼 수 있는 다이어리 페이지 폴더
    - 에디트: 마지막으로 작성한 일기를 수정 또는 삭제
    - 페이지 라우팅 구현하기: 스위치 문과 유사
    - 페이지 이동 구현하기:  경로로 분리된 페이지 간의 이동 방법, 링크 컴포넌트 사용 ,클라이언트 사이드 렌더링으로 페이지 이동하면 속도가 맹 ㅜ빠름
